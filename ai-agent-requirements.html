LLM models and providers

What each AI agent needs to run

Which language model each agent uses, who provides it, and what you supply: on SonarQube Cloud, on SonarQube Server and for Gitar. Click an agent to fold its branch, hover to focus on it.

Provided by Sonar Your own provider or key Models Gitar
SonarQube ServerProviders are registered once per instance

An instance administrator adds providers under Administration › Configuration › AI capabilities › LLM providers. Each agent then picks its own provider and model on its own page.

SonarQube ServerNetwork access to your models

SonarQube Server and the agent hosts both need outbound access to your provider. When an agent runs, code and issue details go to that provider, and its terms apply.

GitarBring your own model

Must be enabled for your organization and is set up by an organization admin. One provider serves traffic at a time, and Gitar still picks the model for each task.

No LLM of their ownSonar Vortex and the MCP Server

Both work inside your developers' coding agent, which brings its own model. Vortex verification uses Sonar's analysis engine, not an LLM.

Sources: SonarQube Server 2026.5 documentation (LLM providers, Hunter Agent, Remediation Agent, Enable AI CodeFix), SonarQube Cloud documentation (Administer the Remediation Agent, Enable AI CodeFix, Hunter Agent) and the Gitar documentation (Bring Your Own Model).
